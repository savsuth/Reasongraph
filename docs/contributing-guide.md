Contributions are made through [GitHub Issues](https://github.com/savsuth/Reasongraph/issues) and [Pull Requests](https://github.com/savsuth/Reasongraph/pulls). This page describes the tooling the repository already uses, so local results match what CI checks.


## Issue Workflow

Open or find an issue before starting work. The repository provides issue templates for bug reports, feature requests, documentation, and support questions.

The pull request template asks contributors to wait for the issue to be assigned to them before opening a PR, to avoid duplicate work.


## Development Setup

```bash
git clone https://github.com/savsuth/Reasongraph.git
cd Reasongraph
pip install -e ".[dev]"
pre-commit install
```

The `dev` extra in `pyproject.toml` installs pytest, pytest-cov, pytest-asyncio, black, isort, flake8, mypy, pre-commit, jupyter, and ipykernel. CI uses Python 3.11.


## Code Style

Style is enforced by the hooks in `.pre-commit-config.yaml`:

- **black** with a line length of 88
- **isort** with the `black` profile and a line length of 88
- **flake8** with a max line length of 88, ignoring `E203` and `W503`
- **yamllint** for YAML files (max line length 120)
- General hygiene hooks: trailing whitespace, end-of-file newline, YAML/JSON/TOML validity, merge-conflict markers, large files (over 1000 KB), and debug statements

Run every hook against the whole tree with:

```bash
pre-commit run --all-files
```


## Tests

Tests live in `tests/` (configured in `[tool.pytest.ini_options]`). Tests that need external services or API keys carry the `integration` marker and can be skipped:

```bash
pytest -m "not integration"
```


## Building the Package

```bash
pip install build
python -m build
```

The CI workflow (`.github/workflows/ci.yml`) also builds the Explorer frontend in `explorer/` with `npm ci` and `npm run build`, and checks that the built wheel contains it.


## Dependencies

CI installs from `requirements-ci.txt`, a hash-pinned lock file generated by uv. Do not edit pins in it by hand. After changing dependencies in `pyproject.toml`, regenerate it with:

```bash
uv pip compile pyproject.toml --python-version 3.11 --extra all --generate-hashes -o requirements-ci.txt
```

CI fails if the file is out of date with `pyproject.toml`, and the Security workflows run `pip-audit` against it.


## Documentation

Documentation lives in `docs/` and is built with Mintlify. Navigation is defined in `docs/docs.json`. Validate changes before opening a PR:

```bash
python docs_check.py
```


## Pull Request Checklist

The [pull request template](https://github.com/savsuth/Reasongraph/blob/main/.github/pull_request_template.md) covers:

<Check>The change is linked to its issue</Check>
<Check>The change was tested locally, with tests added for new functionality</Check>
<Check>The package builds successfully (`python -m build`)</Check>
<Check>Relevant documentation, examples, and API reference are updated</Check>
<Check>Breaking changes are called out with a migration path</Check>
